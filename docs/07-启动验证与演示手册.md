# 在线考试系统 —— 启动验证与演示手册

> 用途：**手动把项目跑起来并演示一遍**。部署到服务器看 `05-部署手册.md`；本文只讲本机从零到能点的完整顺序。
> 全部命令在 Git Bash（Windows）下验证过；标 ⚠️ 的是本机必踩的坑。

## 一、先看环境（30 秒）

```bash
java -version        # 需要 17
node -v              # 需要 18+，本机 22
docker version       # Docker Desktop 必须在运行
```

⚠️ **Docker Desktop 必须手动启动**（开始菜单点开）。命令行 `docker desktop start` 会被安全策略拦，不要试。

```bash
docker ps            # 能列出容器就说明引擎起来了
```

|---|---|
| JDK 17 | `D:\develop\jdk\current`（junction，已指向 17.0.2） |
| Maven 仓库 | `D:\develop\maven\repository`（settings 已配阿里云镜像） |
| 项目根 | `E:/workspace/online-exam` |

## 二、第 1 步：起中间件（MySQL / Redis / 对象存储）

```bash
cd /e/workspace/online-exam/deploy
docker compose up -d          # 只起中间件；api/web 在 app profile 里，不会跟着启动
docker compose ps             # 期望：mysql healthy、redis healthy、minio up
```

首次启动会自动执行 `sql/01-bootstrap.sql` 与 Flyway 迁移，不需要手动建库建表。

端口：MySQL `3306`、Redis `6379`、对象存储 `9000/9001`。

> 起不来先看 `docker compose logs mysql | tail -20`。镜像源不稳定时的绕法见 `deploy/README.md`。

## 三、第 2 步：起后端（8080）

### 情况 A：只是跑起来演示，不改代码

```bash
cd /e/workspace/online-exam/backend
java -jar target/oes-backend-1.0.0-SNAPSHOT.jar
```

看到 `Started OesApplication in x seconds` 即成功。**这个终端不要关**（要关就另开一个窗口做后续操作）。

### 情况 B：改过后端代码，需要重新打包

```bash
cd /e/workspace/online-exam/backend
# ⚠️ 先杀掉占用 jar 的进程，否则打包报 "Unable to rename ... .jar to .jar.original"
netstat -ano | grep ":8080" | grep LISTENING
taskkill //PID <上面查到的PID> //F

mvn -B -DskipTests package
java -jar target/oes-backend-1.0.0-SNAPSHOT.jar
```

### 情况 C：用 Maven 直接跑（不产出 jar）

```bash
cd /e/workspace/online-exam/backend
mvn spring-boot:run
```

### 起来后立刻验三件事

```bash
curl -s http://localhost:8080/api/ping                       # {"code":0,...,"java":"17.0.2"}
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/doc.html   # 200
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"teacher","password":"123456"}'            # 200 + token
```

`doc.html` 是 Knife4j 接口文档：标题「在线考试系统 API」，左侧按 `00-系统` ~ `09-主观题复核` 共 10 组，右上角 **Authorize** 填登录拿到的 token 即可调试受保护接口。

## 四、第 3 步：起前端（5173）

```bash
cd /e/workspace/online-exam/frontend
npm install --registry=https://registry.npmmirror.com --cache .npm-cache   # 首次才需要
TMP=$PWD/.tmp TEMP=$PWD/.tmp npm run dev
```

浏览器打开 **http://localhost:5173**。

`/api` 由 Vite 代理到 8080，**后端必须先起**，否则登录会报网络异常。

⚠️ **本机专属坑**：按需引入后，dev 首次打开某个页面时若发现新依赖会触发重优化，需要批量删 `node_modules/.vite` 下的临时目录，被本机的安全删除策略拦下时表现为**进程直接退出**。遇到就执行：

```bash
cd /e/workspace/online-exam/frontend
git clean -fdxq node_modules/.vite
# 然后重新 npm run dev
```

若不想折腾 dev，也可以直接看**生产构建产物**（更接近验收状态）：

```bash
TMP=$PWD/.tmp TEMP=$PWD/.tmp npm run build
npx vite preview --port 4173      # 打开 http://localhost:4173
```

## 六、演示顺序（建议 8 分钟走完）

### A. 教师端（`teacher` / `123456`）

1. **首页** — 四个快捷入口，说明模块划分。
2. **题目管理** — 分类树 + 951 题；按题型/难度筛选；点「新增」看五类题型的表单切换；「批量导入」可下载模板。
3. **试卷管理** — 打开一份试卷看详情抽屉（规则 + 按题型分组 + 题目预览）；演示「按规则抽题」与「发布」。
4. **考试管理** — 发布一场考试（绑已发布试卷、时间窗、时长）；状态由草稿转已发布。
5. **记录统计** — 选一场有成绩的考试，展开后依次看：
   - KPI（开考/提交/平均分/及格率）
   - **分数分布**，右上角可切「按百分比 / 按 5 分」
   - 成绩明细，点「复核」可给主观题改分并重算总分
   - 「导出成绩单」：≤5000 行直接下载；大数据转后台，完成后出现**「下载」按钮**（需手动点）

### B. 学生端（`student` / `123456`）

1. **我的考试** — 卡片列表，已交卷的显示得分，「查看成绩」进成绩页。
2. 进入一场进行中的考试 → **作答页**：
   - 右上角倒计时（服务端时间校准，改本机时钟无效）
   - 改答案会自动暂存，右上角显示「已自动保存 HH:mm:ss」
   - 简答题有字数计数（0/2000）
3. **交卷** → 弹窗确认 → 跳转成绩页：
   - 总分、客观/主观分、及格状态
   - **考试未结束时正确答案与逐题得分显示为「考试结束后公布」**（防提前泄题，这是有意的）

### C. 管理员（`admin` / `123456`）

1. **用户管理** — 角色/状态筛选；勾选多行可**批量启用/停用**（自己那行不可勾）；单行可重置密码、强制下线、删除（有答卷的用户不能删，只能停用）。

# 停前端：Ctrl+C
# 停后端：Ctrl+C，或
netstat -ano | grep ":8080" | grep LISTENING

# 停中间件（保留数据）
cd /e/workspace/online-exam/deploy && docker compose stop

# 连数据一起清掉（慎用）

## 八、常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录报「网络异常」 | 后端没起，或 8080 被占 | `curl localhost:8080/api/ping`，不通就查后端窗口报错 |
| `mvn package` 报 `Unable to rename ... .jar.original` | jar 被运行中的进程锁住 | 跑 `scripts\stop-port.cmd 8080` 再打包（VS Code 的打包任务会自动先停） |
| dev server 启动后自己退出 | 见第四节 P-23 坑 | `git clean -fdxq node_modules/.vite` 后重启 |
| `npm install` 报 `EPERM` | 默认缓存目录无写权限 | 加 `--cache .npm-cache` |
| `vite build` 报 `Access is denied` | esbuild 写系统临时目录被拦 | `TMP`/`TEMP` 指到项目内 `.tmp` |
| `npm : 无法加载文件 ...\npm.ps1，因为在此系统上禁止运行脚本` | PowerShell 执行策略为 Restricted，`.ps1` 垫片被拒（`npm` 会优先命中山 `npm.ps1`） | 改用 `npm.cmd run dev`（本仓库的 VS Code 任务已改成 `.cmd` 调用）；或把 VS Code 默认终端切到 Command Prompt |
| 前端页面样式全乱/无样式 | 按需引入的样式没进来 | 先确认用的是最新构建；看 `docs/02-开发日志.md` D-038 |
| Flyway 启动报校验和不匹配 | 改了已经执行过的迁移文件 | 不要改历史迁移，新增 `V6__xxx.sql` |
| 中文变问号 | 客户端字符集不是 utf8mb4 | 连接串保持 `characterEncoding=utf8`；导入 SQL 时先 `SET NAMES utf8mb4` |

## 九、附：用 VS Code 启动（更省事，尤其调试）

命令行能跑，但 VS Code 有两个它替代不了的好处：**断点调试**和**不用记路径**。代价是首次打开要等 Java 语言服务器索引（30 秒 ~ 2 分钟）。

### 需要装的扩展

工作区已带推荐列表（`.vscode/extensions.json`），打开项目时右下角会提示安装：`Extension Pack for Java`、`Spring Boot Extension Pack`、`Vue - Official`。

### 配置放在哪

`.vscode/` 已包含 `launch.json`、`tasks.json`、`settings.json`，其中 `settings.json` 把 JDK 固定到 `D:/develop/jdk/jdk-17.0.2`（不指 `current` 链接，避免切换时 IDE 缓存错版本）。

> 注意：`.vscode/` 在 `.gitignore` 里，属于本机配置，不进仓库。若希望验收时别人也能一键跑，把这行去掉再提交即可。

### 启动步骤

| 步骤 | 操作 |
|---|---|
| ① 起中间件 | `Ctrl+Shift+P` → **Tasks: Run Task** → `中间件：启动（compose up -d）`（Docker Desktop 仍需先手动打开） |
| ② 起后端 | 左侧 **Run and Debug** → 选 `后端：启动/调试（8080）` → `F5`。可打断点，改完代码重启即可 |
| ③ 起前端 | **Tasks: Run Task** → `前端：dev（5173）`（该任务已内置 `TMP/TEMP`，不用手写） |
| ④ 调前端 | 再按 `F5` 选 `前端：浏览器调试（需先起 dev）`，会用 Edge 打开 5173，可在 `.vue` 里下断点 |

想一次起好后端 + 前端，用 `全栈：后端 + 前端一起调`（复合配置，会同时启动两个调试会话）。

### 常用任务（`Ctrl+Shift+P` → Tasks: Run Task）

| 任务 | 用途 |
|---|---|
| `一键准备：中间件 + 后端打包` | 冷启动第一步：起 compose，再打包（自动先停 8080 释放 jar 锁） |
| `后端：打包（自动先停 8080）` | 改完后端代码后重新打包；**不用再手动 taskkill** |
| `后端：停 8080` | 调 `scripts/stop-port.cmd`，只杀 8080 的监听进程，不影响其他 Java 进程 |
| `后端：跑测试` | `mvn test`，期望 38 全绿 |
| `前端：构建` / `前端：预览产物（4173）` | 生产构建与产物预览（更接近验收状态） |
| `前端：清 vite 缓存（dev 崩溃后用）` | 就是 P-23 那个坑的解法，不用记命令 |

### 和命令行的取舍

| | 命令行走 | VS Code |
|---|---|---|
| 冷启动速度 | 快（`java -jar` 直接起） | 稍慢（IDE 索引 + 编译） |
| 断点调试 | 要手工加 `-agentlib:jdwp` | `F5` 就行 |
| 改代码后重启 | 手动 kill + 打包 + 起 | 点重启按钮 |
| 中间件 | 都要 Docker Desktop 手动打开 | 同左，没区别 |

**结论**：只想把系统跑起来看效果，命令行更快；要排查问题、打断点，VS Code 明显省事。

### 关于停服脚本（踩过的两个坑）

`scripts/stop-port.cmd <端口>` 是纯 ASCII 的批处理，用 `netstat -ano` 找监听 PID 再 `taskkill`。为什么不写成一行内联命令：

- **不要在任务里直接调 PowerShell 并写 `$_`**：任务终端本身可能就是 PowerShell，外层会先把 `$_` 展开成空值，内层收到的是 `Stop-Process -Id  -Force`，报「参数 Id 是空值」，结果**一个进程都没杀掉**，紧接着打包就撞上 jar 锁。
- **`.cmd` 文件里不要写中文注释**：cmd.exe 按 OEM 代码页（本机 GBK）解析，UTF-8 中文会变乱码并破坏 `for` 循环的括号结构，典型表现是 `'listening' 不是内部或外部命令`。

脚本内部用了 `setlocal enabledelayedexpansion` + `!LASTPID!`：IPv4/IPv6 会各列一条监听记录，而 `%LASTPID%` 在括号块里是解析期展开、始终为空，会重复杀同一个 PID。
