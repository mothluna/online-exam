## 五、不可违背的技术约束

这一节是本文最有价值的部分。下面每条都是踩过坑之后才定下来的，**改动相关代码前必须先读**。

### 5.1 答案锁定：考试结束前不能下发「答案」和「逐题得分」

- **约束**：`GET /student/attempts/{id}/result` 在 `exam.endTime` 之前，必须返回 `correctAnswer = null` 且 `score = null`。
- **为什么**：不只是防抄答案。**判断题答「对」得 0 分，等于告诉考生答案是「错」**——逐题得分本身就是答案信息。
- **违反后果**：答案锁定形同虚设，同场次后考的人可以直接拿分。
- **位置**：`ExamTakingServiceImpl.result()` 里的 `released` 判定。
- **历史**：E-065 实现时即同时锁定 `correctAnswer` 与逐题 `score`，并实测「未结束的考试下，答案与逐题分泄漏数为 0」。**别只锁 `correctAnswer`**——这是最容易想当然写错的一处。

### 5.2 判分：总分必须等于各题得分之和，取整方式必须对称

- **约束**：分值内部按 ×100 存整数（`ScoreUtil`）；单题得分取整方式与满分取整方式必须一致。
- **为什么**：半对取整若不对称，会出现「每题都对但总分差 1 分」，或者满分题拿不到满分（D-018）。
- **违反后果**：学生申诉时无法自证，且统计页的均分与明细对不上。
- **位置**：`ScoreRules` + `ScoreUtil`；`ScoreRulesTest` 22 条用例覆盖了这些边界，改判分必须同步加用例。

### 5.3 题干归一化是不可逆承诺

- **约束**：`StemNormalizer` 的归一化结果用于**唯一键去重**（同题库内题干唯一）。
- **为什么**：历史数据已按旧规则入库，改规则会让旧数据之间出现「本该判重却没判重」。
- **违反后果**：导入时重复题干拦不住，需要写数据修复脚本。
- **要做的话**：新增规则必须**同时**提供存量数据重算方案，否则不要动。

### 5.4 任何权限相关变更，必须递增权限版本号

- **约束**：改角色、停用、重置密码、删除用户，都必须 `INCR oes:authver:{userId}`。
- **为什么**：JWT 是无状态的，签发后 120 分钟内一直有效。递减版本号是唯一能让旧 token 立刻失效的手段（D-022）。
- **违反后果**：「停用后仍能操作」「降级后仍是管理员」这类越权。
- **位置**：`AuthInterceptor` 校验 `ver` 声明与 `authService.currentAuthVersion(userId)`；业务侧在 `UserServiceImpl` 里递增。

### 5.5 交卷必须 CAS + 事务提交后再做副作用

- **约束**：`UPDATE ... WHERE status = 'IN_PROGRESS'`，影响行数为 0 即视为重复提交；分数汇总、Redis 清理放在 `afterCommit`。
- **为什么**：防「连点两次交卷」与「超时任务与手动交卷并发」导致重复判分（D-016）。
- **违反后果**：一份答卷被判两次，`is_pass` 与总分被后一次覆盖。

### 5.6 统计与分布：固定条数 SQL，禁止 N+1

- **约束**：考试聚合列表固定 3 条 SQL；分布固定 1 条；明细分页固定 3 条。
- **为什么**：6001 份答卷时 N+1 会打出上千次查询（D-020）。
- **代价**：分档规则（`LEAST(FLOOR(...),9)`）与及格口径（`is_pass=1`）写进了 SQL。**这是已知的边界**，自检时被点过一次：聚合口径放在 mapper 属于数据访问职责，但要能解释「改分档方式只改一条 SQL，不影响服务编排」。

### 5.7 作答链路优先「不阻断考生」

- **约束**：暂存答案遇到非法取值时，**清洗而不是抛 400**——单选题剔除非法键、判断只收「正确/错误」、简答截断 2000 字，接口仍返回 200，并把被清洗的题号回传，前端提示一次。
- **为什么**：暂存整体失败会让考生以为答案丢了、卡在「存不上」状态（§3.3、E-080）。
- **例外**：结构性错误（题目不属于本卷）仍抛 400，那是客户端 bug，不能咽下去。

### 5.8 前端收到 409 必须分辨是哪一种

- **约束**：`40904`（会话冲突）**绝不能**走「自动交卷」，只有「已超时/已提交」才自动交卷。
- **为什么**：多标签页冲突时若自动交卷，会把这个窗口的过期状态当作最终答案提交（E-085）。
- **位置**：`TakeExamView.vue` 的 `flush()` 错误分支，按 `response.data.code` 分流。

### 5.9 倒计时以服务端时间为准

- **约束**：剩余时间 = `deadline`（服务端下发）− 服务端时间偏移，不使用本机 `Date.now()` 直接减。
- **为什么**：改本机时钟不能延长时间（D-032）。
- **位置**：`TakeExamView.vue` 的 `tick()` 与 `serverTimeOffset`。

### 5.10 状态回滚不是可选项

- **约束**：列表里的开关（用户启停、题目上下架）失败后必须回滚 UI 状态。
- **为什么**：Element Plus 的 `v-model` 会先改值再发请求，失败不回滚会显示错误状态（D-029）。

## 六、本机环境专属的坑（换机器可能不复现，但会浪费你半天）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | `mvn package` 报 `Unable to rename ... .jar.original` | jar 被运行中的后端进程锁住 | 跑 `scripts\stop-port.cmd 8080` 再打包；VS Code 任务已自动串联 |
| 2 | 停服命令报 `Stop-Process: 参数 Id 是空值`，一个进程没杀 | 任务终端是 PS，命令里又嵌套同一解释器，`$_` 被外层提前展开为空 | **不要**写内联嵌套命令，统一调 `stop-port.cmd` |
| 3 | `.cmd` 报 `'listening' 不是内部或外部命令` | 脚本里写了中文注释，cmd 按 GBK 解析 UTF-8 破坏了 `for` 括号结构 | 批处理**只写 ASCII** |
| 4 | `npm : 无法加载文件 npm.ps1，因为在此系统上禁止运行脚本` | 执行策略 Restricted，`npm` 命中 `.ps1` 垫片 | 用 `npm.cmd` / `npx.cmd`；VS Code 任务已改 |
| 5 | `npm run dev` 打开第二个页面后进程静默退出 | Vite 二次优化要批量删 `node_modules/.vite/deps_temp_*`（50+ 文件），被安全删除垫片拦 | 已用 `optimizeDeps.include` 枚举 118 个 style 入口规避；残留时 `git clean -fdxq node_modules/.vite` |
| 6 | 探测 5173 显示「未启动」但浏览器能开 | Vite 绑 IPv6 `::1`，用 `127.0.0.1` 探测会误判 | 一律用 `localhost` |
| 7 | 脚本往 `/tmp` 写文件失败 | Windows Git Bash 无 `/tmp` | 统一写项目内 `frontend/.tmp` |
| 8 | 传 `-S"E-053"` 给 git 无输出；访问 `/dashboard` 变成 Windows 路径 | MSYS 路径自动转换 | `MSYS_NO_PATHCONV=1` |
| 9 | 启动报 Flyway 校验和不匹配 | 改了已执行的 `V1`~`V5` | 不要改；要改加 `V6`，或 `flyway repair`（仅限开发库） |
| 10 | 容器相关操作全失败 | Docker Desktop 未启动（引擎关闭时 3306 也拒连） | 先手动打开 Docker Desktop，`docker ps` 能看到三个容器再继续 |

> 判断「服务活没活」的统一方法：`curl -s http://localhost:8080/api/ping` 返回 `{"code":0,...}`。

## 九、四类常见改动怎么做

### 9.1 加一个接口

1. `dto/` 放请求体（带 `@NotNull` 等校验注解），`vo/` 放响应
2. `service/` 加接口方法 → `service/impl/` 实现，**业务只写这里**
3. `controller/` 只做 `@Valid` 接收 + 调 service + `R.ok(...)`，**不要写 if/for/计算**
4. 需要新错误码：加到 `ResultCode`，避开已用段（`400xx` 参数、`403xx` 权限、`409xx` 冲突）
5. `@Tag` 已按 controller 分好组，方法加 `@Operation(summary=...)` 即可，Knife4j 自动收录

### 9.2 加一个页面

1. `api/xxx.ts` 定义类型与请求函数（复用 `utils/request.ts` 的 `get/post/put`）
2. `views/xxx/XxxView.vue`，页面内组件放 `views/xxx/components/`
3. `router/index.ts` 注册，`meta` 里写 `title` 与 `roles`（守卫据此拦截）

## 十一、责任边界

**这套代码目前能做什么**：单机、单实例、演示与校内小规模使用。题库 953 题、考场 6912 份答卷的规模下，接口响应与页面渲染都实测正常。

**不能承诺什么**：
