## 一、部署形态与端口

```
浏览器 ──> oes-web (Nginx :8081，容器内 :80)
                │  静态资源 + /api 反向代理
                ▼
          oes-api (Spring Boot :8080)
           │            │            │
        MySQL :3306   Redis :6379   对象存储 :9000
```

| 服务 | 容器名 | 宿主机端口 | 说明 |
|---|---|---|---|
| web | oes-web | 8081 | Nginx，生产入口 |
| api | oes-api | 8080 | 后端（/doc.html 可看接口文档） |
| mysql | oes-mysql | 3306 | 库 `oes`，账号 `oes/123456` |
| redis | oes-redis | 6379 | 口令 `redis123456` |
| 对象存储 | oes-minio | 9000 / 9001 | S3 端口 / 控制台（RustFS） |

> 容器内的地址一律用 Compose 服务名（`mysql` / `redis` / `minio` / `api`），不要写 `localhost`。

## 二、方式 A：Docker Compose 一键部署（推荐）

### 2.1 前置条件

- Docker Desktop 已启动（本机需手动启动，见环境检查报告）
- 首次构建需要能拉取 `maven` / `node` / `nginx` / `eclipse-temurin` 基础镜像

### 2.2 步骤

```bash
cd deploy
cp .env.example .env        # 首次；生产环境务必修改其中的口令
docker compose --profile app up -d --build
```

`--profile app` 会额外启动 `api` 与 `web` 两个服务；不加 profile 时只起中间件（本地开发用法）。

首次启动会自动完成：

1. MySQL 容器执行 `sql/01-bootstrap.sql`（字符集、应用账号 `oes`）；
2. `api` 启动时由 Flyway 执行 `V1`~`V4` 迁移，建全部业务表；
3. 用户表为空时写入三个演示账号（`app.seed.enabled` 控制，生产建议关闭）。

### 2.3 验证

```bash
docker compose --profile app ps                  # api/web 为 running
curl -s http://localhost:8080/api/ping           # {"code":0,...}
curl -s -I http://localhost:8081                 # 200 text/html
```

浏览器打开 `http://localhost:8081`，用 `admin / 123456` 登录。

### 2.4 日志与停止

```bash
docker compose --profile app logs -f api         # 后端日志（含 traceId）
docker compose --profile app logs -f web         # Nginx 访问日志
docker compose --profile app stop                # 停止（保留数据）
docker compose --profile app down                # 删容器（保留数据卷）
```

## 三、方式 B：本机进程部署（无 Docker 应用层）

中间件仍用 Compose，后端 jar 与前端静态文件跑在宿主机：

```bash
# 1) 中间件
cd deploy && docker compose up -d

# 2) 后端
cd ../backend
mvn -DskipTests package
java -jar target/oes-backend-1.0.0-SNAPSHOT.jar        # :8080

# 3) 前端
cd ../frontend
npm install --registry=https://registry.npmmirror.com --cache .npm-cache
npm run build                                          # 产物在 dist/
# 用 Nginx 指向 dist/，并把 /api 反代到 http://127.0.0.1:8080
```

Nginx 参考配置见 `frontend/nginx.conf`（把 `proxy_pass http://api:8080` 改为 `http://127.0.0.1:8080`）。

## 四、配置项

后端全部通过环境变量覆盖，默认值见 `backend/src/main/resources/application.yml`。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MYSQL_HOST` / `MYSQL_PORT` | localhost / 3306 | 数据库地址 |
| `MYSQL_USER` / `MYSQL_PASSWORD` | oes / oes123456 | 应用账号（非 root） |
| `REDIS_HOST` / `REDIS_PORT` | localhost / 6379 | 缓存 |
| `REDIS_PASSWORD` | redis123456 | Redis 口令 |
| `MINIO_ENDPOINT` | http://localhost:9000 | S3 兼容服务地址 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | minioadmin / minio123456 | 对象存储账号 |
| `MINIO_BUCKET` | oes-file | 导入/导出文件桶，启动时自动创建 |
| `JWT_SECRET` | 开发默认值 | **生产必须覆盖**，HS256 要求 ≥32 字节 |
| `app.seed.enabled` | true | 是否在空库写入演示账号，生产建议 `false` |

修改 `deploy/.env` 后，`docker compose --profile app up -d` 会重建受影响容器。

## 六、运维

### 6.1 备份

```bash
# MySQL 逻辑备份
docker exec oes-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction oes' > backup_oes_$(date +%F).sql

# 对象存储与 Redis 数据在命名卷中，随卷备份
docker run --rm -v oes_minio-data:/data -v ${PWD}:/backup alpine tar czf /backup/minio_$(date +%F).tar.gz -C /data .
```

### 6.2 升级

```bash
git pull
cd deploy
docker compose --profile app up -d --build
```

数据库变更通过 Flyway 版本文件（`V5__xxx.sql`）随启动自动执行；**禁止手工改已执行过的迁移文件**，否则校验和不匹配会拒绝启动。

### 6.3 回滚

- 应用：`docker compose --profile app up -d --build` 指向旧提交重新构建；
- 数据：停止 api → 用备份恢复 `oes` 库 → 启动。注意新版本已执行的迁移不会自动回退，回滚代码前先确认表结构兼容。

### 6.4 日志与排障

| 现象 | 排查 |
|---|---|
| api 起不来，日志有 `Communications link failure` | MySQL 未就绪：确认 `docker compose ps` 中 mysql 为 healthy |
| `Flyway ... Validate failed` | 迁移文件被改动：恢复原文件，或新增版本而不是修改旧版本 |
| 页面 404 / 刷新白屏 | Nginx 缺 `try_files ... /index.html`（见 `frontend/nginx.conf`） |
| 前端请求 502 | api 未启动或容器名不对：`proxy_pass` 必须指向 `api:8080` |
| 接口 401 但刚登录 | 检查 `JWT_SECRET` 是否在重启后变化（令牌全部失效） |

## 七、上线安全清单

- [ ] 修改 `.env` 中 MySQL / Redis / 对象存储口令，不要沿用示例值
- [ ] `JWT_SECRET` 换成随机 ≥32 字节字符串，且不提交到仓库
- [ ] 设置 `app.seed.enabled=false`，或上线后立即修改三个演示账号密码
- [ ] 8080 / 3306 / 6379 / 9000 不对公网暴露，只保留 8081（或前置 HTTPS 网关）
- [ ] 配置 HTTPS（证书挂到 Nginx，监听 443 并跳转）
- [ ] 定期备份 `oes` 库与 `oes_minio-data` 卷
- [ ] 日志保留策略：默认按天滚动 15 天，按磁盘容量调整

## 八、常见问题

**镜像拉取失败**：国内镜像源不稳定，可用前缀拉取后重命名（见 `deploy/README.md`）。

**8081 / 8080 被占用**：改 `docker-compose.yml` 中 `web` / `api` 的宿主机端口即可，容器内端口不变。

**首次构建很慢**：后端镜像需要下载 Maven 依赖（约 300MB），前端需要 `npm ci`；构建层已按「先 pom、后源码」拆分，后续改代码不会重复下载依赖。

**Windows 下前端构建报 `Access is denied`**：把 `TMP`/`TEMP` 指到项目内 `.tmp` 目录（见根目录 README）。
