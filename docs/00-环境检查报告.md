## 二、详细记录

### 2.1 JDK（唯一需要决策的项）

```
JAVA_HOME = D:\develop\jdk\current
javac     = 21.0.12.1
java      = 21.0.12.1  (OpenJDK 64-Bit Server VM)
Maven 运行时 JDK = 21.0.12.1
安装目录  = D:\develop\jdk\jdk-21.0.12.1+1（仅此一个版本）
编译+运行验证：Hello.java 编译 exit=0，输出 JAVA_OK 21.0.12.1 → JDK 本身完好
```

**问题**：课题要求 Java 17，当前只有 21。

**影响评估**：

- Spring Boot 3.2 最低要求 17，**运行在 21 上没有问题**，功能层面不会受阻。
- 但存在两个实际风险：
  1. **Lombok 版本**：JDK 21 需要 Lombok ≥ 1.18.30，旧版会直接编译失败（`java.lang.ExceptionInInitializerError: com.sun.tools.javac...`）。这是最常见的踩坑点。
  2. **验收口径**：若评审按"Java 17"核对（`java -version` 或 IDE SDK），运行在 21 上可能被判不符。
- 若坚持用 21，必须在 `pom.xml` 固定 `maven.compiler.release=17` + `lombok 1.18.32`，并接受"字节码 17 / 运行时 21"的混合状态。

**建议**：装一个 JDK 17 与之共存，通过 `JAVA_HOME` 切换，不改动现有 21。这是风险最低的做法。

### 2.2 中间件（三项全缺，是当前最大阻塞）

```
3306 / 6379 / 9000 / 9001 / 8080 / 5173  →  均无监听
Windows 服务中无 mysql* / redis* / minio*
C:\Program Files、D:\develop 等常见路径下未找到 mysql.exe / redis-server.exe
```

端口全部空闲是**好消息**：装好后不会与现有软件冲突。

### 2.3 Docker（不可用）

```
docker CLI      = 29.9.2（仅客户端）
Docker Desktop  = 未安装
com.docker.service = 不存在
docker info     = 返回空（无守护进程）
WSL             = wsl.exe 被安全策略拦截，无法探测发行版
```

即：`docker` 命令在，但没有引擎，`docker run` 会直接报 "cannot connect to the Docker daemon"。且 WSL 状态未知，安装 Docker Desktop 存在不确定性。

**结论**：不能依赖 `docker compose up` 一键起环境，需走原生安装。

### 2.4 依赖源与缓存

```
Maven: 无 ~/.m2/settings.xml，本地仓库为空 → 首次构建会全量下载（Spring Boot 全家桶约 200~400MB）
npm:   registry = http://registry.npmmirror.com（已配国内镜像，很好）
```

首次 `mvn clean package` 预计 3~8 分钟（取决于带宽）。建议补一个阿里云 Maven 镜像，把时间压到 1~2 分钟。

### 2.5 其他

- VS Code 位于 `D:\Microsoft VS Code\bin\code.cmd`，做前后端开发够用；若想要 Spring 的 Bean 跳转/端点视图，IntelliJ IDEA 社区版体验更好（非必需）。
- 磁盘充足，MySQL 数据目录 + MinIO 数据 + Maven 仓库合计占用预计 <15GB。

## 三、缺口清单与处置方案

按"是否阻塞开发"排序：

| 优先级 | 缺口 | 处置方案 | 预计耗时 |
|---|---|---|---|
| P0 | MySQL 8 | 下载 `mysql-8.0.36-winx64.zip` 解压至 `D:\develop\mysql`，`mysqld --initialize-insecure` 初始化，控制台方式启动（免管理员） | 15 min |
| P0 | Redis | 官方不支持 Windows。用 **Memurai Developer**（Redis 7.2 兼容，开发免费）或社区 Redis 7.x Windows 构建，解压即用 | 10 min |
| P0 | MinIO | `https://dl.min.io/server/minio/release/windows-amd64/minio.exe`，单文件，`minio server D:\data\minio --console-address :9001` | 5 min |
| P1 | JDK 17 | Temurin 17 zip 解压至 `D:\develop\jdk\jdk-17.0.x`，项目/IDE 指向它，系统 `JAVA_HOME` 可保持不变 | 10 min |
| P2 | Maven 镜像 | 生成 `~/.m2/settings.xml` 指向阿里云，首次构建提速 3~5 倍 | 2 min |

**不做 Docker 的理由**：Docker Desktop 依赖 WSL2/Hyper-V，当前 WSL 探测被拦截、无法确认可用性；而三项中间件都有免安装的 Windows 版本，原生跑反而更可控、启动更快（考试系统本地开发不需要容器隔离）。

## 六、补充记录：实际搭建过程（2026-11-26 16:03 ~ 16:20）

### 6.1 Docker Desktop 复核

初检未扫到 Docker Desktop，实际为**用户级安装**：

```
版本 4.98.0
路径 C:\Users\Admin\AppData\Local\Programs\DockerDesktop
（docker context 中已有 desktop-linux，说明曾正常使用过）
```

由用户手动启动后，引擎就绪：

```
ServerVersion=29.9.2 | OS=linux | Arch=x86_64 | Mem≈8GB
Docker Compose v5.6.1
```

> 注：`docker desktop start` 在此环境被安全策略拦截（需拉起 `wsl.exe`），只能由用户手动启动。启动后所有 `docker` 命令均正常。

### 6.2 镜像拉取：镜像源不稳定

守护进程配置了三个国内镜像源（`docker.1ms.run`、`docker.xuanyuan.me`、`docker.m.daocloud.io`），实测：

| 镜像 | 结果 |
|---|---|
| `mysql:8.0.36` | 经 `docker.m.daocloud.io` 成功 |
| `redis:7.2-alpine` | 经 `docker.m.daocloud.io` 成功 |
| `minio/minio` | **全部源 denied / not found** |

**处置**：改用可达的镜像前缀拉取后 `docker tag` 回原名，不改动守护进程配置（改 `daemon.json` 需重启 Docker Desktop，而重启同样依赖被拦截的 wsl.exe）。

```bash
docker pull docker.m.daocloud.io/library/mysql:8.0.36
docker tag  docker.m.daocloud.io/library/mysql:8.0.36 mysql:8.0.36
```

### 6.3 MinIO 不可用的原因（重要）

不只是镜像源问题，**MinIO 开源版已停止分发**：

```
$ curl -I https://dl.min.io/server/minio/release/windows-amd64/minio.exe
HTTP/1.1 410 Gone

The open-source MinIO Server, MinIO Client (mc) and MinIO KES projects are
archived and no longer maintained... These files are no longer served from this site.
```

- 官方二进制下载：**410 Gone**
- Docker Hub `minio/minio`、`bitnami/minio`：各镜像源均 `denied`
- `quay.io/minio/minio`：`401 UNAUTHORIZED`

### 6.4 替代方案：RustFS（S3 协议兼容）

选用 `rustfs/rustfs:latest`：

- 完全兼容 S3 API，**MinIO Java SDK（io.minio）可直接对接**，代码零改动，只需改 endpoint；
- 同样的 9000（S3）/ 9001（控制台）端口布局；
- 迁移成本仅一行：`OBJECT_STORAGE_IMAGE` 环境变量，将来若重新获得 MinIO 镜像可无缝切回。

**协议层验证（boto3 实测通过）**：

```
bucket oes-file: CREATED
put/get object: minio-compatible check
list objects: ['import/202611/test.txt']
S3 API OK
```

控制台：`http://localhost:9001/rustfs/console/`（账号 `minioadmin` / `minio123456`）
健康检查：`http://localhost:9000/minio/health/live` → 200

> 过程记录册应如实记两条：① 选型时按课题要求锁定 MinIO；② 实施时发现上游已停止分发，改用 S3 兼容实现并保留一键切回能力。这比"假装用的是 MinIO"更可辩护。
